# Contributing / Участие в проекте

**[Русский](#русский) · [English](#english)**

## Русский

Благодарим за желание улучшить Megastructures. Поддерживаются исправления ошибок, документация, оптимизации и новые собственные ресурсы для существующих игр.

### Как предложить изменение

1. Проверьте существующие Issues и откройте новый, если задача ещё не обсуждается.
2. Создайте форк и отдельную ветку от `main`.
3. Делайте небольшие независимые изменения. Не меняйте игровой контент и лицензии без связанной с ними задачи.
4. Перед Pull Request выполните проверки, описанные в README конкретной игры. Если проверка неприменима или не была запущена, укажите это.
5. Заполните шаблон Pull Request и опишите изменения, тесты и влияние на производительность/ассеты.

Не добавляйте `Library/`, `Temp/`, `UserSettings/`, локальные сборки, секреты, токены, персональные данные, транскрипты или абсолютные пути пользователя. Большие игровые сборки публикуются через Releases, а не в Git.

### Лицензии и сторонние материалы

- Отправляя код, вы соглашаетесь распространять его под [MIT](LICENSE).
- Отправляя собственные не-кодовые ассеты, вы соглашаетесь распространять их под [CC BY 4.0](LICENSE-ASSETS.md).
- Добавляйте только материалы, на которые у вас есть необходимые права. Указывайте источник, автора и лицензию в `THIRD_PARTY_NOTICES.md` и соответствующем `ASSET_NOTICES.md`.
- Не присваивайте CC0 и не меняйте лицензию чужого материала без явного разрешения. Модели Tripo3D из Bulwark имеют особый статус; не удаляйте это ограничение без подтверждения прав.
- Сохраняйте существующие уведомления об авторских правах и лицензиях.

Правила поведения: [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Уязвимости сообщайте по инструкции [SECURITY.md](SECURITY.md), а не в публичном Issue.

## English

Thank you for helping improve Megastructures. Bug fixes, documentation, optimisations and new original resources for the existing games are welcome.

### How to propose a change

1. Check existing Issues and open one if the task is not already being discussed.
2. Fork the repository and create a focused branch from `main`.
3. Keep changes small and independent. Do not change game content or licensing without a related reason.
4. Run the checks documented in the relevant game's README before opening a Pull Request. State when a check is not applicable or was not run.
5. Complete the Pull Request template and describe the changes, tests and performance/asset impact.

Do not add `Library/`, `Temp/`, `UserSettings/`, local builds, secrets, tokens, personal data, transcripts or user-specific absolute paths. Large game builds belong in Releases, not Git.

### Licenses and third-party material

- By submitting code, you agree to license it under [MIT](LICENSE).
- By submitting original non-code assets, you agree to license them under [CC BY 4.0](LICENSE-ASSETS.md).
- Submit only material you have the necessary rights to. Record its source, author and license in `THIRD_PARTY_NOTICES.md` and the relevant `ASSET_NOTICES.md`.
- Do not dedicate third-party work to CC0 or change its license without explicit permission. Bulwark's Tripo3D models have a special status; do not remove that limitation without confirmed rights.
- Preserve existing copyright and license notices.

Code of conduct: [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). Report vulnerabilities privately using [SECURITY.md](SECURITY.md), not a public Issue.
