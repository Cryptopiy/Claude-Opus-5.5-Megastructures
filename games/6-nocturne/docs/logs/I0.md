- Exact attribution: `-alloc-profile <file>` (dev player: 300 frames of Unity profiler data into <file>.raw once steady) +
  `BatchTools.AnalyzeGcProfile -profile-in <raw>` (Editor: every GC.Alloc sample summed by thread and marker stack;
  QA/reports/I0_gc_profile.md). I0-alloc09 / I0-gcprof01, 169 frames: per-frame allocations ONLY under
  `UnityEngine.InputModule!NativeInputSystem.NotifyBeforeUpdate() [Invoke]`: PreUpdate.NewInputUpdate 16.90 B/frame (0.994 per
  frame), PostLateUpdate.PlayerSendFrameStarted > FrameEvents.NewInputBeforeRenderUpdate 16.90, FixedUpdate.NewInputFixedUpdate 4.73
  (0.278 per frame = the 50 Hz fixed steps) = 38.5 B/frame = the recorder's 38.7. Everything else is event-driven (log lines
  with their stack traces in the dev player 18 B/frame averaged, UI Toolkit repaint of the fade 4.8, URP 4.0 at the beat change).
- Cause (IL of UnityEngine.InputModule.dll, System.Reflection.Metadata dump): NotifyBeforeUpdate is
  `bool (NativeInputUpdateType t) { if (onShouldRunUpdate != null && !onShouldRunUpdate(t)) return false; onBeforeUpdate?.Invoke(t); return true; }`;
  Unity's native-to-managed invocation boxes the bool return value: one 17-byte object per native input update (ProcessInputUpdate
  returns void and allocates nothing). Engine code: it cannot be removed while the Input System updates. The statistical probe's
  split (NewInputUpdate / PlayerSendFrameStarted / NewInputFixedUpdate) was right after all.
- Fix: `NocInput.RestrictNativeUpdates` (player only) sets the native active update mask to Dynamic (internal
  NativeInputSystem.SetActiveUpdateMask, bound by reflection once): the Fixed updates (only used in ProcessEventsInFixedUpdate mode)
  and the BeforeRender updates (only used by XR tracked devices) no longer run, leaving one boxed bool per frame at any frame rate.
  The project-wide actions are disabled too (never read). NocFogMath.StateAt's per-frame array was the other framework allocation
  (fixed in f33d88a, before the first measurement).
- Measured after the fix (commit 2f62a53): dev recorder I0-alloc10 18.8 B/frame over 16 622 frames (17 = the box, 1.8 = event /
  time-based); release Mono heap I0-alloc11 31.5 B/frame over 16 539 frames (one 32 B size class per frame), was 71.0 (I0-alloc06)
  and 125 in A1's run. Our own code: 0 B per frame.
